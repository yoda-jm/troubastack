One name · two halves · three modules

A troubadour composes. A joglar performs.

The name is a pun in two halves, and both map onto the architecture. Trouba: a troubadour composes, a joglar performs — editing and performing are different jobs with different failure modes, so they are different programs. Stack: those programs are a pile of modules rather than one monolith — an editor, a server that also bakes, a presenter — each swappable on its own and joined by one authoritative server and one baked artifact. It is what the mark draws: three planes, stacked.

Compose

TroubaStudio

A fullscreen, canvas-first web editor. Everyone marks up the same chart at the same time.

  • Low-latency wet ink, per-member layers
  • Shapes, text, highlights, conductor cues
  • Chord transposition that preserves line count, so annotations stay anchored
  • Offline honesty: read-only and visibly so — nothing dies silently
Serve & bake

TroubaCore

One Go binary holding the single authoritative truth — and the bake pipeline.

  • Bakes a setlist into one band-wide concert bundle
  • Offers it in-app; devices download and keep it
  • Studio pixels and baked pixels come from the same renderer, parity-tested
  • Everything on disk in one directory you can tar
Perform

TroubaStage

The presenter, inside the mobile app. No account, no login, no network.

  • Pedal and volume-key page turns
  • Night mode, count-in, facing pages on wide tablets
  • Per-role layer defaults and a song drawer
  • Screen stays awake while you play

In the rehearsal room

The marks are the point.

A band's real knowledge lives in the margins — capo 2, watch me here, everyone in on the last chorus. TroubaStack keeps those marks first-class: owned by the member who made them, layered, and carried all the way onto the stage.

  • Per-member layers — your fingering notes stay yours; the conductor's cues reach everyone.
  • Realtime, multi-user — annotate the same chart together and see it land.
  • Personal song cues — an icon and a colour per member, riding along in the band bake.
  • Setlists you can drag — encores, benched songs, per-item transposition.

Show night

The venue's wifi will fail. It does not matter.

A concert is downloaded once and lives on the device as a single file. While you perform, the app makes no request at all — aeroplane mode, a dead router, a basement with no signal: the presenter is reading a file. There is no account to be logged out of and no server to be unreachable. Immersive by default: system bars gone, the whole screen is the score; one tap brings the chrome back.

Ergonomics, not features

Built for a music stand, late at night.

  • Hardware page turns — a Bluetooth pedal or the volume keys.
  • Night mode — for a stage lit by one lamp.
  • Count-in and a live tempo meter on the chrome.
  • Facing pages on a wide tablet; scroll mode when you prefer it.
  • Your layers, filtered to you — the bundle carries the whole band; the presenter shows your view.

Self-hosted, on purpose

Your band's music, on your own box.

No SaaS, no seat pricing, no third party holding your setlists. A home server or a cheap VPS is plenty — one binary behind Caddy, TLS provisioned automatically, and every byte of state in one directory you back up with tar.

Run it for a band

The supported install: Docker Compose + Caddy, with automatic Let's Encrypt certificates.

# set DOMAIN=band.example.org
cp deploy/.env.example deploy/.env
cd deploy
docker compose up -d

Multi-stage build — the SPA is embedded into the binary at compile time, and the runtime can bake.

Try it in a minute

Builds the editor, embeds it, seeds demo data and serves the whole thing locally.

make setup
make demo
# → http://localhost:8080

Needs Go 1.26+ and Node 24+. Add pdftoppm to bake PDFs.

The app

Kotlin/Compose Multiplatform — Android today, iOS proven in the simulator.

make app
adb install -r \
  androidApp-debug.apk

No toolchain? Every CI run on main also builds a debug APK you can download from the Actions run.

Packaging status, honestly. The compose build above is the supported install. There is no published registry image, no GitHub Releases binary and no store or F-Droid listing yet. The Android build you can scan for below is the debug APK from CI — unsigned for release, and GitHub asks you to sign in before it hands over a build artifact. A signed release APK is the remaining half of the deploy story.

Zero servers

A real concert, committed to the repo.

A baked bundle ships in the source tree, so you can see the presenter work without running anything at all. It is copyright-safe by construction: one original song plus traditional and public-domain material, flattened by the real bake pipeline — not a mockup.

  • One artifact for the whole band — roster, every layer owner-tagged, every member's cues.
  • Filtered at view time — an auto-match on connect, or a one-tap “who are you?”.
  • Push it straight to a device and present.
