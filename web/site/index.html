One name · two halves · three modules

A troubadour composes. A joglar performs.

Trouba: editing and performing are different jobs with different failure modes, so they are different programs. Stack: a pile of modules rather than one monolith — an editor, a server that also bakes, a presenter — joined by one authoritative server and one baked file. It is what the mark draws: three planes, stacked.

Compose · annotate

TroubaStudio

A fullscreen, canvas-first web editor. Everyone marks up the same chart at the same time.

  • Per-member layers, low-latency live ink
  • Shapes, highlights, text, conductor cues — with line styles and arrow ends
  • Jump marks: a matched pair of segno, coda or symbol, linked by a direction arrow
  • Text charts: chords over lyrics, typeset; transpose without moving a mark
  • Tags and search, and a tag panel that keeps the vocabulary clean
  • Stage notes shown under your annotations, to recopy properly
Serve · bake

TroubaCore

One Go binary holding the single authoritative truth — and the bake pipeline.

  • Bakes a setlist into one band-wide concert file, offered in-app
  • Studio pixels and baked pixels come from the same renderer
  • Marks anchored to their words — re-render the chart, they stay put
  • Knows which file and page every baked page came from
  • All state in one directory you back up with tar
Perform

TroubaStage

The presenter, inside the mobile app. No account, no login, no network.

  • Page turns from a keyboard or BLE-MIDI pedal, learned in one press
  • Four reading schemes — never a white flash in a blackout
  • Tap a jump mark and land on the passage it points at
  • Count-in, live tempo, facing pages on a wide tablet
  • Note mode: write on the page, send it to the band
  • Your layers, filtered to you — the file carries the whole band

In the rehearsal room

The marks are the point.

A band’s real knowledge lives in the margins — capo 2, watch me here, everyone in on the last chorus. TroubaStack keeps those marks first-class: owned by the member who made them, layered, and carried all the way onto the stage.

  • Per-member layers — your fingering stays yours; the conductor’s cues reach everyone.
  • Realtime — open the same song in two browsers and draw.
  • Lines that say something — dashed, dotted, an arrow at either end.
  • Jump marks — a matched pair of landmarks; on stage, tap one and land on the other (more below).

Sixty songs, one box

Find a song by what it is.

Tag songs the way the band talks about them — opener, slow blues, needs work — then find them the same way.

  • Suggestions with counts — the existing tag is the easy path, so the vocabulary doesn’t fragment.
  • Loose words, strict tags — type freely; a picked tag becomes a chip, and chips combine.
  • Tags on every row — click one to filter by it.
  • One panel to tidy them — rename, merge, delete, with the exact count before you confirm.

No PDF? No problem

Type the chords. Get a page.

Write a chart the way you would in a text message — chords on one line, lyrics under them — and Studio typesets it: sections, columns, a performance note like (x3) at the end of a chord line.

  • Transpose per setlist item, and the annotations stay on their words.
  • Two columns when the song is long — the width buys a larger type, not a denser page.

The running order

Cut a setlist into one file.

Drag the songs into order, drop in an intermission, transpose a song for tonight’s singer. Then bake: Core flattens every page, every layer and every member’s cues into a single concert file the app downloads and keeps.

  • Personal song cues — an icon and a colour per member, flashed on song entry.
  • Choose what shows — decide which layers are on when the concert opens.
  • One file for the whole band — each player sees their own view of it.

Show night

The venue’s wifi will fail. It does not matter.

A concert is downloaded once and lives on the device as a single file. While you perform, the app makes no request at all — aeroplane mode, a dead router, a basement with no signal: the presenter is reading a file. Immersive by default, the whole screen is the score; one tap brings the controls back.

Ergonomics, not features

Built for a music stand, late at night.

  • Pedal page turns — a Bluetooth keyboard pedal or a BLE-MIDI one, taught with one press.
  • Four reading schemes — paper, warm, night, amber — for a stage lit by one lamp.
  • Count-in and a live tempo meter on the controls.
  • Facing pages on a wide tablet; scroll mode when you prefer it.
  • Hard to leave by accident — a stray edge swipe doesn’t end the concert.

The killer feature

Tap the segno. Land on the passage.

A chart says D.S. al coda, back to the sign, to verse 2 — and on a tablet that used to mean swiping back through pages mid-song, looking for a small symbol. A jump mark makes the score do it.

  1. Place a pair in Studio — the source, then the destination. Both wear the same glyph and colour (segno, coda, a circle, a star), so a player matches them by eye, as on paper.
  2. See where it goes — select either end: a dashed arrow names the direction, a chip says which page the other end is on, one button swaps the way it points.
  3. Tap it on stage — a quick “Go”, or straight there if you switch the confirmation off. In scroll mode you land on the passage itself, not the top of its page.

The link is between the two marks, not a page number: re-render the chart, add a page, and it still points at the same passage.

The loop closes

Write it on the stand. Find it at your desk.

Rehearsal is where the real corrections happen, and nobody puts the tablet down to open a laptop. So Stage has a pencil: draw on the page, and the note goes back to Studio — as a picture of what you wrote, to recopy properly, not as a mark that pretends to be finished.

  1. Note mode on the tablet — write straight on the page you’re playing from.
  2. Send it — one tap for the lot, or an auto-upload window for a live session.
  3. See it in Studio — under your annotations, on the page it was drawn on, even if the chart has changed since.
  4. Recopy, then remove — the note was a reference; your annotation is the real thing.

Self-hosted, on purpose

Your band’s music, on your own box.

No SaaS, no seat pricing, no third party holding your setlists. A home server or a cheap VPS is plenty — one binary behind Caddy, TLS provisioned automatically, and every byte of state in one directory you back up with tar.

Run it for a band

The supported install: Docker Compose + Caddy, automatic Let’s Encrypt certificates.

# set DOMAIN=band.example.org
cp deploy/.env.example deploy/.env
cd deploy
docker compose up -d

Pulls a published linux/amd64 image — no host toolchain. Or docker pull vincentleligeour/troubastack:latest; the README has the standalone docker run recipe.

Try it in a minute

Builds the editor, embeds it, seeds a demo band and serves the whole thing locally.

make setup
make demo
# → http://localhost:8080  marie / demo

Needs Go 1.26+ and Node 24+. Add pdftoppm to bake PDFs. A baked demo concert is also committed to the repo — the app can present it with no server at all.
