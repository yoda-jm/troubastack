# TroubaStage test fixtures

Committed baked-bundle fixtures for the shared loader/presenter tests (A02/A03). They conform to
the container spec ([`docs/design/08-bundle-container.md`](../../../../../../../docs/design/08-bundle-container.md))
and are consumed by `FixtureBundleTest` (androidUnitTest).

There are two kinds of fixture here, and they are **remade in different ways** — read this before
regenerating anything:

- `demo/` and `torture/` are **generated by the dev tool `core/cmd/mkbundle`** and are deterministic
  (same flags ⇒ byte-identical output), so regenerating should produce an empty diff.
- `baked/` is a **frozen snapshot of a real `web/bake` output** and is **not** produced by
  `mkbundle`. `make fixtures` does not touch it. See its entry below for why, and how to remake it.

**Do not hand-edit.** Regenerate `demo/` + `torture/` with:

```
make fixtures          # from the repo root
```

which runs:

```
cd core && go run ./cmd/mkbundle \
  -out ../app/shared/src/commonTest/resources/fixtures/demo \
  -torture ../app/shared/src/commonTest/resources/fixtures/torture
```

`make fixtures` regenerates **only** `demo/` and `torture/` — `baked/` is deliberately not an output
of `mkbundle` (see below).

## Contents

- `demo/` — a valid bundle (2 songs × 3 pages, 2 overlays per page): loads with **zero issues**.
- `torture/` — the never-crash variants (I12):
  - `missing-blob/` — valid manifest, one referenced raster deleted → `Loaded` + a per-page issue.
  - `bad-json/` — truncated `bundle.json` → `Failed`.
  - `empty/` — valid manifest, zero songs → `Loaded`, empty.
  - `no-manifest/` — blobs only, no `bundle.json` → `Failed`.
- `baked/` — a **real `web/bake`-produced** bundle (unpacked), consumed by
  `FixtureBundleTest.realBakerBundle_loadsPerformable`. It guards that the bundle the *actual* baker
  emits still loads performable (1 song, ≥1 page, ≥1 surviving overlay layer, non-empty roster,
  zero issues) — the seam where a bake-format drift would sit silent until a musician hit it.
  `mkbundle` can't stand in for this: the real baker emits an overlay blob **only** for a layer with
  drawn objects, while `mkbundle` synthesises overlays unconditionally — same container, different
  population. That difference is the whole point of the fixture, so **do not regenerate `baked/`
  with `mkbundle`** — it would replace the real-baker artefact with a synthetic one and delete what
  the test is for.
- `baked-current/` — the **regeneration arm** (A61), remade by **`make fixtures-baked`** from TODAY's
  baker, consumed by `FixtureBundleTest.regeneratedBakerBundle_loadsPerformable`. Same performable
  contract as `baked/`, but opposite job: `baked/` proves an OLD bundle still loads (frozen forever);
  `baked-current/` proves the reader tracks what the CURRENT baker emits. Regenerating it is expected
  to change it (see below) — that is fine; it is `baked/` that must never move.

### The two real-baker fixtures, side by side

| fixture | job | regenerated |
|---|---|---|
| `baked/` | an **old** bundle — new readers still load bundles predating later fields (the compat arm) | **never** (frozen) |
| `baked-current/` | a **current** bundle — the reader tracks what the baker emits today | `make fixtures-baked` |

Both are synthetic, no band data: concert "Template Concert", song "Sound Check" (one page), one
annotation layer "Notes", member/baker "Alex" (admin).

**`make fixtures-baked`** runs the real pipeline (poppler + the Node `web/bake` worker) in-process via
`core/cmd/mkbaked`, writing only `baked-current/`. It resolves the worker the same way the server does
(T128), honouring `TROUBA_BAKE_CLI` / `TROUBA_NODE` / `TROUBA_PDFTOPPM`, and **skips cleanly** — a
message, exit 0, nothing written — when node / pdftoppm / the built `cli.js` are absent (the case a
contributor without the toolchain hits). The Makefile rebuilds `web/bake` first when `node_modules`
are present, because a **stale `cli.js` fails** the overlay bake with
`request.json must have { doc, pages, overlayWidth > 0 }` — the overlay path is version-skew-sensitive.

**`baked-current/` is NOT byte-reproducible** (UUIDs, `bakedAt`, and the real raster vary per bake), so
running `make fixtures-baked` produces a non-empty diff — expected, the same honesty `baked/` gets.
Refresh it deliberately (e.g. after a real bake-format change), not reflexively.

**`baked/` is remade by hand only** (frozen): it was produced through the server bake API at the A58
commit (`42b488ba`); to reproduce, bake a single-song concert with one annotated page through a matched
`core` ↔ `web/bake` build and unpack into `baked/`. Do **not** point `make fixtures-baked` at it.

## Images

`demo/` and `torture/` images are **synthetic test patterns** (borders, blocks, translucent
rectangles), not real baked pages — the one stroke renderer is `web/ink` and Go never renders
strokes (I8; see the mkbundle doc). `baked/` is the exception: its page raster and overlay blob are
the **real** `web/bake` output.
