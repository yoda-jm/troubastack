## The two field bugs (both reported by VLL, both dead)

- **T32 — "wet ink doesn't hold, no error, no traffic"** (`1cb1286`). His console
  line was the key: `crypto.randomUUID is not a function`. The API exists only in
  SECURE contexts (HTTPS/localhost) — his box is plain-HTTP non-localhost, so every
  create path threw before any notice. Invisible to every e2e forever, because
  localhost IS a secure context. Fix: `newUuid()` (getRandomValues v4 fallback) +
  **VLL's directive made structural**: commit-path errors surface via the T30
  notice, and a global error banner + render boundary catch everything else —
  "it is not normal to just die silently" is now enforced by a committed guard that
  deletes `randomUUID` and runs the draw flow (red-proven against pre-fix main).
- **T34 — "stuck in nav after removing the 2 fingers"** (`c2d75a9`). Root cause:
  two-finger nav pointers were never captured, so a finger lifting over a chrome
  button delivered its `pointerup` off-canvas → a stale `pointersRef` entry made
  every later single finger a "second finger" → permanent nav until reload. Fix:
  isPrimary self-heal + capture; my gate condition added the `endGesture()` on
  healing a LIVE nav (both-lifts-missed leaves a stuck CSS transform otherwise) +
  a third reproducer variant. All three flavors now e2e-gated.
