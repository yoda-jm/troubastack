# Task pack — prioritized, agent-executable work items

Each `Txx-*.md` file in this directory is a **self-contained task** written so a competent
coding agent (or human) can execute it without reading the whole repo history. Files are
numbered in **priority order** — do them top-down unless a task says otherwise.

## Ground rules (apply to every task)

1. **Read `docs/ARCHITECTURE.md` first.** The numbered invariants (I1…I15) are normative.
   If your change would violate one, stop and flag it instead.
2. **One task = one branch = one PR.** Branch from `main`, name it `task/Txx-short-name`.
3. **Never edit** `core/internal/webassets/dist/` (build artifact, regenerated by `make embed`)
   or anything under a `gen/` directory.
4. **Verification commands** (run from the repo root):
   - `make test` — Go tests (engine, stores, HTTP API). Must stay green.
   - TS typecheck — note the `web/` workspace is nominal: there is **no root lockfile**;
     studio installs standalone (`make setup` runs `npm install --no-workspaces` in
     `web/studio`) and ink resolves from source via Vite alias + tsconfig `paths`.
     So install per-package, then use studio's tsc for all three:
     ```
     make setup                      # once; installs web/studio + Playwright
     cd web/ink && npm ci --no-workspaces   # ink lockfile; --no-workspaces or npm reparents to the (absent) root lockfile
     cd web && TSC=studio/node_modules/.bin/tsc; \
       $TSC --noEmit -p ink && $TSC -b studio && $TSC --noEmit -p bake
     ```
     (studio's tsconfig.json is a SOLUTION file — `-p studio` compiles nothing;
     use `-b studio` so tsc follows the app + node references.)
   - `make e2e` — Playwright end-to-end suite (needs `make setup` once). Must stay green
     for any task touching `web/studio`.
   - `make demo` — builds everything and serves the seeded app at `http://localhost:8080`
     (demo users: `marie` / `leo` / `sasha` / `maestro` / `flora` / `cory`, password `demo`).
     Use this to eyeball UI changes.
5. **E2E selectors:** the Playwright specs in `web/studio/e2e/` select by `data-testid`.
   When you change markup, keep existing `data-testid` attributes attached to the
   equivalent element, and update specs only when a flow genuinely changed.
6. Each task lists its own **acceptance criteria**. All of them must pass before the task
   is done. If a criterion is impossible as written, report why rather than approximating.

## App track (A-series) — the Kotlin/Compose mobile app

`app/` is a structural scaffold (three `expect/actual` seams, all bodies `TODO()`, the
Gradle build intentionally inert). The A-series turns it into a working Android app,
**TroubaStage-first**: the presenter is the product's stage-time face and its contract
is *resilient and read-only* — it must never crash mid-performance, and its only
user-changeable state is reading behavior (navigation, display fit, layer visibility),
never writes. It is also **offline and login-free** (I12): no account, session, or
unlock stands between app launch and performing a locally-stored bake; the viewer's
role (for layer default visibility) is a local preference, not an identity. Auth exists
only in the Studio webview (A06) and the future downloader. See A04 for the full
contract.
