# T16 — Seed PDFs render em-dashes as mojibake

**Priority:** anytime · **Size:** XS · **Area:** `core/cmd/seed`

## Context

The seeded demo PDFs show `â€"` where an em-dash belongs (e.g. the page title
"Wonderwall — Vocals") — found while hand-baking the demo bundle. The seed's PDF
generator writes UTF-8 bytes into PDF text strings whose font encoding is
single-byte (WinAnsi/Latin-1), so the three UTF-8 bytes of `—` render as three glyphs.

## Changes

1. In `core/cmd/seed`'s PDF text emission, either (a) properly encode text to WinAnsi
   (em-dash is 0x97 there), or (b) if that fights the generator's structure, sanitize
   the strings (`—` → `-`, plus any other non-Latin-1 chars) with a comment. Prefer (a)
   if it's ≤ ~20 lines.
2. Reset + reseed (`rm -rf core/troubadata && make demo`) and confirm titles render
   correctly in Studio.
3. Note: `docs/demo/demo-concert.tstage` was hand-baked from the *old* seeds and shows
   the mojibake in its raster; add one line to `docs/demo/README.md` saying it will be
   regenerated by the real bake (B02) — do not hand-rebake it for this.

## Acceptance criteria

- Seeded song/file titles show a correct dash in the Studio viewer (screenshot).
- `make test` green; seeding a fresh server produces no errors.
