**Priority:** high (VLL 2026-08-10: better demo material + annotations — "freehand

`docs/screenshots`. No product code changes — demo *content* + the tooling that

## Why (audit findings, 2026-08-10)

Audited the demo chart PDFs + the seeded showcase (`core/cmd/seed/annotations.go`)
against what the product can do:

1. **The `icon` stamp type (T51) is never seeded.** The wire set is
   `freehand|line|rect|ellipse|text|highlight|icon` (`web/ink/src/objecttype.gen.ts`),
   the baker renders `TypeIcon`, glyphs.json ships 19 tintable glyphs (incl.
   `warning`) — zero stamps in the demo. Worse, the seed **hand-draws** a ⚠ as three
   freehand paths (`warnSign`/`warnTriangle`, `annotations.go:176-189`).
2. **VLL's canonical T51 scenario is missing** ("semi-transparent blue square around
   a verse + a blue shaker icon in the corner"). No seeded object uses the explicit
   `fill`/`stroke`/`blend` style fields (`httpapi/annotations.go:50-52`).
3. **Freehand highlighter is underused** — a few 4-point, near-straight `hiSwipe`s
   over single words; they read as synthetic, not as a musician's marker. Nothing
   swipes a full lyric line; the orchestra parts have **no ink on the music at all**
   (three margin texts).
4. **Placement is 60+ hand-tuned magic numbers** with no guarantee a highlight
   covers its word — and it has drifted (`docs/screenshots/demo-chart-annotated.png`
   and `open-road.annotations.json` show an older showcase than the builders).
5. **Thin pages**: house tab + amazing grace fill ~⅓ page; Greensleeves p.2 and the
   Open Road riff page carry no ink, so page-turns show a bare chart.

## Design (decided)

### 1. Anchors, not magic numbers

Two regimes, honest about what each PDF allows:

- **Generated charts (mkcharts) — exact by construction.** `mkcharts` writes
  `<name>.anchors.json` beside each PDF: every text run it draws as
  `{page, text, x0, y0, x1, y1}` in [0,1]² page coords (fpdf cursor +
  `GetStringWidth`, converted once in the shared helpers `chordLine` /
  `sectionLabel` / `barChart` / `header`). Committed, regenerated by the same
  `go run ./cmd/mkcharts` invocation. The seed looks anchors up by
  `(page, substring, occurrence)`.
- **Engraved PDFs (Mutopia/Greensleeves) — named, calibrated anchors.** Notes,
  chords, dynamics are music-font glyphs: **no text extraction can place them**.
  Each showcase PDF gets a committed hand-calibrated
  `<name>.anchors.json`: named entries
  `{key, desc, page, x0, y0, x1, y1}` where `desc` states the musical target in
  words (e.g. `"opening motif, bars 1–2, system 1"`). §5 defines how Opus
  calibrates and proves them. `pdftotext -bbox` MAY seed entries whose target is a
  genuine text run (titles, tempo words, Greensleeves lyrics — verify the string
  actually extracts); everything musical is calibrated visually. **Draft boxes are
  given in §4 (Fable-measured from 100 dpi renders, ±0.01)** — start from those.
- **The seed consumes only anchors.** New helpers in `annotations.go`:
  `anchorOf(file, key)` / `anchorText(file, substring, n)`, then
  `highlightAnchor(...)` (swipe sized FROM the bbox), `ringAnchor(...)`,
  `labelNear(...)` (text in adjacent clear space + connector that crosses no other
  anchor). After migration, **no naked coordinate literal remains in
  `annotations.go`** — every position traces to an anchors JSON.
- **Containment test (red-first).** A `cmd/seed` unit test walks every built
  import: each anchor-bound object must cover/contain its target bbox (tol 0.005).
  Add it BEFORE migrating (it must fail on today's drifted coords), then migrate to
  green.

### 2. Real hand-drawn stroke character (the "real freehand" requirement)

All freehand marks go through one new helper, `handStroke` (and `handRing` for
closed loops), replacing the too-clean `hiSwipe`/`vertBracket` geometry:

- **Slight tilt**: a swipe is never horizontal — end y differs from start y by
  0.3–0.8% of page height, direction varying per mark.
- **Wobble**: 2–3 gentle amplitude bumps (±0.15–0.3% page height) along the path,
  10–16 points, no straight segments longer than ~15% of the stroke.
- **Overshoot**: start ~0.4% before / end ~0.6% after the target bbox, with a
  slight hook at the lift-off (last 2 points curl ~0.3% off-axis).
- **Deterministic**: jitter comes from a PRNG seeded by the object key (idempotent
  re-seed byte-identical; the containment test stays stable — tolerances above
  already cover the jitter envelope).
- `handRing`: a closed wobbly loop whose ends overlap by ~10% arc rather than
  meeting exactly — how a person actually circles something.
- Highlighter style: width ≈ target bbox height ×1.15, opacity 0.35–0.45,
  **explicit `blend:"multiply"`** so it never occludes the print.

The `ellipse` *tool object* still appears (§3) — the tool must be showcased — but
at least two rings in the demo are `handRing` freehand, and brackets get the same
treatment (slightly uneven arms).

### 5. Verification protocol — what Opus MUST do (and show)

**A. Generated charts (automatic):** the containment unit test (§1) against the
mkcharts manifest, in CI. Red-first, then green.

**B. Engraved PDFs (no text extraction possible for music — prove placement on
pixels):**
1. **Ink-under-mark raster test** (new, `cmd/seed` test, skips if `pdftoppm`
   absent — CI has poppler via the bake path): rasterize each annotated engraved
   page at 150 dpi; for every *highlighter swipe* and *ring*, ≥6% of the pixels
   under the stroke band / inside the ring's inner box must be dark (it covers
   actual print, not whitespace); for every *text label and icon stamp*, ≤1.5%
   dark pixels in its bbox (it sits in genuinely clear space). Thresholds are
   constants — tune once, don't loosen to pass (the
   reproduce-before-fixing rule applies).
2. **Visual calibration loop (mandatory, not optional):** composite every built
   import over its page raster (throwaway Go tool or the bake compositor — prefer
   the bake path: it exercises the real `icon` renderer). **View every page and
   every per-mark crop yourself**; adjust the anchors JSON until each mark hits
   the musical target named in its `desc`. Do not land coords you have not seen
   rendered.
3. **Gate artifacts:** attach to the handoff — full composited pages for: Open
   Road p.1 + p.2, house tab, amazing grace, greensleeves p.1 + p.2, ek-violin1,
   canon-violin1, ek-score; PLUS one close-up crop per §3 mark numbered 1–36.
   The review checklist per mark: on-target per `desc` / label+stamp in clear
   space / stroke reads hand-drawn (visible tilt + wobble) / legible at full-page
   zoom / multiply blend keeps print readable underneath.

**C. Product-path checks:** re-seed twice → byte-identical imports (deterministic
jitter, idempotent ids); `-only orchestra` still seeds; bake e2e green; extract
the re-baked `.tstage` hero pages and confirm stamps render (Go `icon` path) —
attach one such page (bundle-rendered, not just the calibration composite).
